## The one thing: backup timeout on pb_ai
- `pb_backup.runs` id 30 (Nov 16 09:00:03 UTC) `failed` — "1 of 17 schemas not saved: pb_ai (dump pb_ai failed (status 500))"; 16 files, 19.9 MB, 45,252 rows, finished in 40 s, alert sent 09:00:44. The folder `2026-11-16/` has every other schema's file.
- Cause (Postgres log 09:00:13 and 09:00:28, both "canceling statement due to statement timeout"): `pb_backup_dump('pb_ai')` runs through PostgREST as service_role, which has no timeout of its own and so inherits authenticator's 8 s. pb_ai is 22.8 MB of JSON now (eval_images 10.9 MB — the quality-run photos; kb_chunks 3.5 MB; its `kb_chunks_backup` copy 3.4 MB; kb_index_parts 1.8 MB; code 1.1 MB). Hot, the dump takes ~3.6 s (1 s to read, 2.6 s to turn 22.8 MB of jsonb into text); cold at 2 AM it crossed 8 s both times. Same mechanism as the pb_daily one-off on Nov 10, but this one will keep happening as the library grows.
- Checked and ruled out: a `SET statement_timeout` on the function itself does not help — the 8 s timer is already running when the statement starts (tested in the database: a 20 s function setting under a 2 s session limit still cancels).
- **Fix for you to run** (SQL editor, nothing deleted; file `feat_triage_2026-11-16/sql/BACKUP_TIMEOUT_OWNER_PASTE.sql`):
  `alter role service_role set statement_timeout = '120s'; notify pgrst, 'reload config';` then a few seconds later `select pb_backup.kick();` to redo today's folder (harmless to run twice). PostgREST applies a role's setting per request, so only calls made with the service key (the edge functions) get the longer limit; users' calls keep 8 s / 3 s. Check a minute later: `select * from pb_backup.runs order by id desc limit 3;` → `done`, 17 files.
- Your call, not mine: `pb_ai.kb_chunks_backup` (2,741 rows, the pre-batch-4 copy from Nov 14) adds 3.4 MB to every night's backup; if the sealed library is good it can be dropped (line is in the file, commented out).
- Nothing in the app is affected; this is only the nightly copy. Supabase's own backups are unaffected.
